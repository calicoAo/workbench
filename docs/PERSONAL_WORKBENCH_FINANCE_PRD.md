# Personal Workbench Finance PRD

版本：v1.0 · 2026-09-17 · R4–R5 待实施  
关联：[总 PRD](PRD_VNEXT.md) · [开发计划](DEVELOPMENT_PLAN_VNEXT.md)

## 1. 目标与边界

Finance 回答：有哪些账户、钱如何变化、花在哪里、预算还剩多少、有哪些即将发生的收支。它是 Workbench 的独立核心域，不以几个余额卡片代替账本。

R4 实现可手工维护和导入的个人账本；R5 提供受控财务投影和外部钱包对账。Workbench Coins、Finance Money、Agent Wallet 三套账本永久分离：做任务获得金币不增加收入，兑换奖励不直接减少银行余额，股票复盘不自动生成证券交易。

首版仅 CNY、个人使用，无银行实时连接、行情、税务、投资建议或直接支付能力。金额用整数分存储，接口传整数字符串或受校验的安全整数，前端不能用浮点累计余额。

## 2. 页面与主要路径

| 页面 | 内容与主要操作 |
| --- | --- |
| 概览 | 总资产／负债／净值、本月收入支出、预算、待确认周期收支；可隐藏金额 |
| 账户 | 现金／银行／支付账户／信用账户，余额、期初与历史，新增／停用／对账 |
| 流水 | 按日期、账户、分类、类型筛选；记收入、记支出、转账、退款、更正与作废 |
| 预算 | 按月总额／支出分类预算、已用／剩余；超出提示不阻止真实记录 |
| 周期收支 | 房租、订阅、工资等模板；到期候选确认、跳过、暂停 |
| 报表 | 月收支、分类支出、账户净变化、余额核对、期间导出 |

移动端 Quick Add 优先支出：金额 → 分类 → 默认账户 → 保存；可以展开日期、备注。转账单独入口，明确转出／转入账户；不会让用户为转账创建一笔支出再创建一笔收入。

## 3. 领域模型与规则

| 对象 | 最小字段／职责 |
| --- | --- |
| FinanceAccount | 名称、类型、币种、是否计入总览、期初日期、归档时间；余额由有效账目派生 |
| FinanceCategory | 收入／支出分类、名称、顺序、是否启用；停用不破坏历史 |
| FinanceTransaction | 类型、发生时间、分类、备注、状态、来源、version；一次用户操作的事务头 |
| FinanceEntry | transactionId、accountId、带符号金额；保存账户余额变动，不建另一套可手填余额 |
| Budget | 月份、可选支出分类、限额；相同范围唯一 |
| RecurringTemplate | 类型、金额、账户／分类、频率、下一发生日期、是否启用 |
| RecurringOccurrence | 模板、应发生日期、待确认／已入账／跳过、生成交易 ID |
| ImportBatch | 批次、文件摘要、来源行键、校验结果与已导入引用 |

FinanceEntry 是本产品的账户变动明细，不扩展为通用企业会计科目系统。

### 3.1 余额与流水

1. 账户余额 = 期初分录 + 全部有效 Entry 金额。资产账户通常为正，信用账户欠款以负数表示；负债卡片按欠款绝对值展示。净值为纳入总览的全部账户带符号余额之和。
2. 收入增加对应账户金额，支出减少；信用账户消费形成更负的余额。
3. 同币种转账是一笔 Transaction 下两条相反 Entry；净值、收入、支出均不因转账本金变化。手续费单独记录为支出，可与转账关联。
4. 信用账户还款是资产账户转入信用账户；不再次记为支出。信用卡消费时已经计入支出。
5. 退款关联原支出，为原分类负支出；不记成普通收入。部分退款累计不得超过原支出，例外调整用明确的余额调整类型。
6. 期初余额与对账调整不计入收入／支出；调整必须说明原因，能回溯到操作记录。
7. 更正使用反向冲正原分录并写入更正分录的同一事务；作废同样保留审计。原账目不硬删除；不能只改账户余额掩盖差额。
8. 已有流水账户只可归档；归档后不用于新交易，历史报表继续可见。所有引用必须属于当前用户且币种一致。

### 3.2 预算、周期、报表

- 月预算按实际发生日期统计支出减退款，转账、期初、对账调整排除；分类预算与总预算分别展示，不能再相加形成重复预算。
- 首版退款在退款发生月减少支出，保留原交易链接；跨月退款不偷偷改已结束月份，报表明确此口径。
- 周期模板生成待确认项，用户确认才入账；唯一 `(templateId, scheduledDate)` 防重复。即使后期允许自动入账，也必须单独授权并可暂停。
- 周期计划不计入真实余额，概览单列“预计收支”；修改模板只影响未来未处理发生项。
- 报表读取同一账本，不维护第二套收入／余额累计值。日期仍使用 Asia/Shanghai。
- 财务记账与悬赏无强制依赖；可把“核对本月账单”作为普通 Task，完成它不会改变账本。

## 4. 数据维护与安全

导入先选择格式映射 → 预览 → 校验币种／金额／账户／分类 → 标记可能重复 → 用户确认。完全相同来源行键只入账一次；相似金额日期仅提示，不自动丢弃。每批有结果报告，失败行可修正重试；不能重试时再插入已成功行。

导出包含账户、分类、交易、分录、预算和周期模板的版本化 JSON；CSV 用于人工查看。全量备份与恢复通过隔离环境演练，恢复后校验账目数量及每账户余额。

编辑采用 expectedVersion，冲突返回 409。收入／支出／转账／退款／更正／导入确认全部接受幂等键，账户变动与交易状态在同一数据库事务。敏感导出、授权、冲正和外部导入有审计记录。

## 5. 分阶段交付

| 子阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| FIN-01 基础账本 | 账户、分类、期初、收入支出、流水、余额核对 | 每个余额可追溯，查询无业务写入 |
| FIN-02 转账与更正 | 双账户转账、手续费、退款、冲正、归档 | 原子性／幂等／并发冲突测试通过 |
| FIN-03 日常管理 | 月／分类预算、周期收支、报表、快速记账 | 计划与真实区分；转账不计收支 |
| FIN-04 数据维护 | 导出、导入预览／去重、对账报告 | 导入重试不重复，恢复余额一致 |
| FIN-05 投影（R5） | 独立敏感授权、账户摘要／预算投影、撤销与审计 | 没有授权时 Bridge Today 看不到财务数据 |
| FIN-06 外部钱包（R5） | 钱包事实读取／交易结果关联、对账与纠错 | 外部钱包有独立服务契约后实施；不在 Finance 模块建影子钱包余额 |

FIN-01–04 构成 R4 完整首版，不得把 FIN-01 的余额展示作为整个 Finance 已完成。

R5 的 Payment Effect 由外部钱包／支付服务拥有执行状态；Workbench 仅在已确认成功且具唯一外部交易 ID 时生成一次关联流水，失败／待定不扣真实余额，退款追加新关联记录。实际资金支付授权、凭据与重试由支付 owner 管理；这里不把调用 Agent 建议视为支付授权。

## 6. 验收样例

| 输入／操作 | 预期 |
| --- | --- |
| 银行期初 1,000 元，现金期初 0；银行转现金 200 元 | 银行 800、现金 200、净值 1,000；收入支出皆 0 |
| 现金花费 30 元后退款 10 元 | 现金 180、本期净支出 20、净值 980 |
| 信用账户初始 0，消费 100，再从银行还款 100 | 消费时负债 100；还款后信用余额 0、银行减少 100；支出只记一次 100 |
| 重复提交同一转账／相同导入来源行 | 返回原结果，不出现第二笔交易或单边分录 |
| 转账第二条 Entry 写入失败 | 整个事务回滚，两账户均无变化 |
| 周期订阅到期但未确认 | 只有待确认项，真实余额不变化 |
| 预算 500、支出 520 | 显示超出 20；保留全部真实流水 |
| 更正／作废已记支出 | 可追溯原记录与冲正，余额和报表同步变化 |
| 两端同时修改同一交易 | 后提交者得到 409，不能覆盖前者 |
| 关闭财务集成授权 | 后续投影请求被拒绝；已存在 Workbench 数据不删除 |
